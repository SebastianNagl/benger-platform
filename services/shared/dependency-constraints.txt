# Shared dependency bounds for services/api and services/workers.
#
# Both images run the code in services/shared, so every third-party package
# that code imports (plus the drivers and protocol libraries it relies on)
# must resolve to the same version in both lockfiles. This file is the one
# place those bounds live. scripts/sync_shared_constraints.py copies it into
# the `[tool.uv] constraint-dependencies` block of both pyproject.toml files
# (uv only reads constraints from there), and its `--check` mode, run in CI,
# fails when the copies drift or when the two uv.lock files resolve any
# package they have in common to different versions.
#
# A constraint only bounds a package; it does not add it to a service. A
# service still has to declare what it imports in its own dependencies.
#
# Exact pins (==) mirror the deliberate exact pins in services/api/pyproject.toml
# so the workers cannot float past them; moving one means editing the api pin
# and this line together (uv lock fails loudly if they disagree). Ranges are
# for packages neither side pins exactly: both locks resolve the newest
# version inside the range, and the --check agreement test catches the rare
# case where one side's other dependencies hold it back.
#
# After editing this file:
#   python3 scripts/sync_shared_constraints.py
#   (cd services/api && uv lock) && (cd services/workers && uv lock)
#   python3 scripts/sync_shared_constraints.py --check

# Database. SQLAlchemy 2.1 resolves postgresql:// to psycopg 3, but both
# services ship psycopg2 only: every worker crashed at import on 2026-09-30
# when the weekly base rebuild floated to 2.1.1. Lift together with a driver
# move.
